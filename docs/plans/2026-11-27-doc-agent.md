# Document AI Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A portfolio demo that extracts fields from invoices and contracts (PDF or image), answers questions about them with quotes that our own code verifies, and shows cost, retries, confidence flags and spend limits on screen.

**Architecture:** A UI-free core package `doc_agent/` (config, documents, schemas, validation, LLM client with retries and budget, extraction, Q&A with quote checking, cached sample results) plus a thin Streamlit app `app.py`. Claude Haiku 5.5 is called through OpenRouter's Anthropic-compatible Messages endpoint with the official `anthropic` SDK.

**Tech Stack:** Python 3.11+, `uv`, `anthropic` (≥ 2.14), `pydantic` v2, `pypdf`, `streamlit`, `reportlab` + `pillow` (sample generation), `pytest` + `pytest-cov`, `ruff`.

**Spec:** `docs/design.md` — read it before starting any task.

## Global Constraints

- Provider: `base_url="https://openrouter.ai/api"`, key sent as Bearer via `anthropic.Anthropic(auth_token=..., api_key=None)`.
- Model: `anthropic/claude-haiku-5.5`. Model, base URL and key are config values only (switch to direct Anthropic = change three values).
- Key from env `OPENROUTER_API_KEY` or a local `.env` (gitignored). Never logged, never shown in UI.
- SDK retries off: `max_retries=0`; our own retry loop handles 429, 5xx, connection errors and timeouts — max 3 attempts, backoff 1s → 2s (+ jitter up to 0.5s). Timeout 60s per request.
- Prices (fallback when `usage.cost` is absent): $0.10 / $0.50 per 1M tokens for prompts ≤ 100,000 input tokens, $0.50 / $2.50 above.
- Daily budget $1.00 (UTC day), per-browser-session budget $0.10.
- Uploads: `.pdf`, `.png`, `.jpg`, `.jpeg`; ≤ 10 MB; ≤ 20 pages.
- Questions: 1–500 characters after stripping.
- Sum check tolerance: `max(0.01, 0.005 * total)`.
- `DEMO_DEV=1` enables the "simulate API failure" control; absent in the public build.
- Everything a user sees (UI, README) is English. No real personal data in samples. No invented claims (clients, accuracy numbers) anywhere.
- Logs record kind, model, tokens, cost, attempts, duration — never document content or the key.
- Effort: `"low"` for extraction, `"medium"` for Q&A. `max_tokens`: 4000 extraction, 2000 Q&A.
- Source files under 400 lines, functions under 50 lines, frozen dataclasses / Pydantic models for data.

## Review Focus

1. A broken, encrypted or mislabeled file ("report.pdf" that is really a PNG or HTML) → a friendly `DocumentError` message, never a stack trace. (Task 3)
2. The model cites a document index or page that does not exist → quote marked `not_found`, no `IndexError`. (Task 7)
3. Amounts like `"USD 1,234.50"`, `"1.234,50 €"`, `"$1,200"`, `""` or `None` → parsed or flagged, never a crash. (Task 4)
4. The budget file is missing, corrupted, or from yesterday → treated as $0 spent today; corrupted file logged and replaced. (Task 2)
5. Streamlit reruns the script on every widget change → an API call happens only on an explicit button press, results live in `st.session_state`, so nothing is charged twice. (Task 9, manual check)
